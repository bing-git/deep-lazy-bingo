## 1. 结论与边界

**存在可优化方案，但当前收益主要来自需求收敛、交付顺序和验证组织，不是已经证明的性能缺陷。**
前后端目录为空，架构也明确尚未生成工程；不能据文档推断已有 API、数据库、授权、模型或页面正在运行。
建议保留现有模块化单体、Art Design Pro 开源版、Spring Boot MVC/Spring AI、PostgreSQL/pgvector 选型。
不建议改框架、拆微服务、另建通用 Agent 平台、任意代理或提前引入复杂队列来制造“优化”。

- 先对齐少数跨文档含义/优先级差异，再按可验证的纵向闭环推进。
- 家庭隔离、对象授权、撤权即时生效、AI 默认关闭/人工审核、来源许可均为**已有要求的落地门槛**，不是新发现的设计缺失。
- pgvector 不是权限边界；家庭服务目录不是代理；儿童和成人健康/私有学习数据不能因聚合、引用或审计扩大披露。
- 所有 OPT 和 AC 是建议方案的后续验收，不表示本次已实现或已通过产品测试；优先级也不覆盖原始需求优先级。
- 仅本报告可写；基线、产品目录、`.github`、`.git`、`.joycode` 均只读。无账本、外部写入、安装、图谱生成或工程启动。

## 3. 十二份需求摘要与验收约束

### R00：总览与统一约定

来源：[00-overview](../requirements/00-overview.md)§1–8，无独立 FR/AC 编号。
范围包含儿童学习、成人学习/健康、受控知识库/AI、服务目录、PC Web；微信小程序仅预留 API 复用。
排除微服务、任意代理/执行、AI 自动发布、完整教材分发、医疗诊断、手表直连；不承诺小程序可用。
家长/成人/儿童/系统管理员边界分开；账号可关联成员，但每请求只能解析一个活动家庭与合法成员身份。
家庭隔离、对象授权、最小披露、脱敏变更追踪、可恢复失败、UTC 存储/家庭时区统计为共同规则。
通用验收要求安全的不存在/无权响应、服务端校验、刷新后持久一致/无重复、桌面与移动可用、每条 P0 至少一个自动化测试层级；后续 OpenAPI、迁移和测试须携需求 ID。

### OPT-03 · P0 · 将撤权传播落实为共用验证场景

### OPT-04 · P0 · 优先固化最小机器可校验契约

### OPT-06 · P1 · 把检索优化建立在小型固定评测集上

### OPT-07 · P1 · 统一事实版本、幂等与聚合口径

## 7. 开放未知、差异与软质量信号

- **U02，偏好/壳能力的阶段优先级。** [管理](../requirements/07-administration-audit-preferences.md)`FR-ADMIN-010/012`将专注模式、主题等维护/恢复列 P0；[工作台](../requirements/02-workspace-global-experience.md)`FR-WS-006/044`将功能列 P1，`005`内容标签也是 P1；[知识库](../requirements/09-knowledge-base-rag.md)`FR-KB-110`和[学习 AI](../requirements/10-learning-ai-experience.md)`FR-LAI-060`又在 P0 壳内要求内容标签。确认各阶段范围，不静默升级或降级。
