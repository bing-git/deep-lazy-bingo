# 前端架构与交互模式

Web 客户端直接基于 [Art Design Pro 开源工程](https://github.com/Daymychen/art-design-pro)搭建，不只是借鉴其视觉风格。具体页面、角色行为与验收标准以[工作台需求](../requirements/02-workspace-global-experience.md)及各业务模块需求为准。

## 技术分层

| 层 | 职责 |
| --- | --- |
| Art Design Pro 开源基座 | 沿用 Vue 3 / TypeScript / Vite 工程、Element Plus 组件封装、路由、布局和主题系统。 |
| 应用壳 | 导航、页面布局、面包屑、全局搜索、通知和响应式菜单。 |
| 领域模块 | 学习、健康、家庭服务、知识库、AI 草稿和家庭管理页面。 |
| 共享组件 | 表格、表单、图表、状态反馈、抽屉和可访问性基础。 |
| API 客户端 | 基于 OpenAPI 契约封装请求、会话、错误、取消和请求追踪。 |
| Pinia | 会话、权限、布局偏好和短期交互状态；服务端仍是业务数据事实来源。 |

目录以选定上游版本为准，在其现有页面、API、路由与组件目录中增加业务代码，不为匹配预设目录重写应用壳。

## 模板接入

1. 固定上游 tag 或 commit，保留 MIT 许可证、版权说明、锁文件及构建配置；运行原有构建作为基线。
2. 保留布局、主题、通用表单和表格；使用上游清理能力或按引用清理演示页面，避免删除公共依赖。
3. 将演示登录、菜单与数据请求替换为 Spring Boot API，删除生产路径中的 Mock、演示账号与模拟指标。
4. 在既有框架内接入家庭业务模块；不从商业版搬运代码，也不重复建设同类基础组件。

## 关键边界

- 导航项由服务端授权数据驱动；路由守卫改善体验，但不替代 API 权限检查。
- 页面通过统一 API 客户端访问后端，不自行拼接服务端地址或维护另一份权限规则。
- 仅在确有跨页面共享价值时使用全局状态；列表、详情和权限相关数据优先由 API 加载。
- 主题、图表、表格和表单共用设计令牌与基础组件；窄屏下改用抽屉、单列和摘要卡片。
- 使用 Art Design Pro 的 MIT 开源工程及其许可覆盖的资源；商业版源码、图标、插画和主题资产不在采用范围内。
