# 运动与饮食需求

## 1. 范围

本模块为成人提供手动运动与餐食记录、营养数值来源、人工修正、趋势和可编辑计划。它帮助用户观察日常行为，不提供医疗诊断、康复方案、自动疾病判断或未经确认的设备数据抓取。

## 2. 核心对象

| 对象         | 必需业务属性                                                      | 说明                                 |
| ------------ | ----------------------------------------------------------------- | ------------------------------------ |
| 运动记录     | 所属成员、开始时间、类型、时长、距离/组数（可选）、主观感受、来源 | 一次真实或用户确认的运动事件。       |
| 餐食记录     | 所属成员、用餐时间、餐次、食材或菜品、份量、估算营养、来源        | 一次用餐及其组成项。                 |
| 营养数值     | 能量、蛋白质、脂肪、碳水等可选字段、单位、估算状态                | 需与来源和人工修正关系关联。         |
| 训练计划     | 所属成员、目标、周期、项目、状态、创建方式                        | P1 的可编辑建议或自建计划。          |
| 健康共享授权 | 授权人与被授权人、数据范围、状态                                  | 由账号与访问控制模块统一管理。       |
| 导入批次     | 成员、来源格式、文件摘要、导入时间、结果                          | P1，用于 CSV/JSON 的受控导入和去重。 |

## 3. 功能需求

### 3.1 运动记录

| ID            | 优先级 | 需求                                                                                                             |
| ------------- | ------ | ---------------------------------------------------------------------------------------------------------------- |
| FR-HEALTH-001 | P0     | 成人必须能创建运动记录，至少填写运动类型、发生时间和时长；距离、组数、强度、备注和主观感受为可选字段。           |
| FR-HEALTH-002 | P0     | 系统必须校验运动记录的时间顺序、数值非负、合理单位和当前成员归属；不能为无权成员创建记录。                       |
| FR-HEALTH-003 | P0     | 成人必须能查看、修改和删除自己的运动记录；修改和删除必须保留操作摘要，避免趋势无原因变化。                       |
| FR-HEALTH-004 | P0     | 运动记录必须标注数据来源，例如手动录入、文件导入或经确认的外部来源；界面不可把估算或导入数据伪装为设备实时数据。 |
| FR-HEALTH-005 | P1     | 成人可按日期、运动类型、来源和计划筛选记录，并以安全范围导出本人数据。                                           |
| FR-HEALTH-006 | P1     | 系统必须能基于已保存记录计算周/月运动次数、总时长、距离和训练连续性，并明确计算周期和最后更新时间。              |

### 3.2 餐食与营养记录

| ID            | 优先级 | 需求                                                                                                     |
| ------------- | ------ | -------------------------------------------------------------------------------------------------------- |
| FR-HEALTH-010 | P0     | 成人必须能创建早餐、午餐、晚餐或加餐记录，并添加一个或多个食材/菜品、份量与单位。                        |
| FR-HEALTH-011 | P0     | 餐食中的热量和营养素必须记录数值、单位、来源和是否为估算；没有可靠数据时允许保持未知，不得补造精确数值。 |
| FR-HEALTH-012 | P0     | 成人必须能人工修改营养估算，并保留原值、修正值、修正来源或说明和修正时间。                               |
| FR-HEALTH-013 | P0     | 餐食记录必须支持查看、修改和删除本人记录；删除后相关趋势重新计算，且界面明确数据已移除。                 |
| FR-HEALTH-014 | P1     | 系统可支持可复用的常用食物或餐食模板，但模板中的营养值必须保留数据来源与更新时间。                       |
| FR-HEALTH-015 | P1     | 系统必须按日、周或自定义范围汇总已记录营养，并明确其为用户输入或估算汇总，而非医疗建议。                 |

### 3.3 计划、共享与导入

| ID            | 优先级 | 需求                                                                                                                            |
| ------------- | ------ | ------------------------------------------------------------------------------------------------------------------------------- |
| FR-HEALTH-020 | P1     | 成人必须能创建、修改、暂停和结束可编辑训练计划，计划由目标、周期和运动项目组成。                                                |
| FR-HEALTH-021 | P1     | 训练计划可由 AI 草稿或手动创建，但采纳 AI 草稿前用户必须可编辑；系统不得自动替换用户已有计划。                                  |
| FR-HEALTH-022 | P0     | 健康记录默认仅本人可见。家长或其他成人访问前必须存在有效的明确授权，且访问范围不得超过授权数据类型。                            |
| FR-HEALTH-023 | P1     | 系统可导入用户确认的 CSV/JSON 健康数据。导入前必须显示记录数量、时间范围、重复风险和字段映射；确认后生成可追踪的导入批次。      |
| FR-HEALTH-024 | P1     | 导入必须按成员、来源标识、时间和内容摘要执行去重策略，不能因重复上传产生重复运动或餐食记录。                                    |
| FR-HEALTH-025 | P2     | 华为手表数据只能通过经过用户授权和确认的 Android 采集端或受支持导入方式进入系统；后端不得假定能够直接读取手表或华为健康云数据。 |

## 4. 健康安全与展示规则

- 所有热量、营养和训练建议都必须明确数据来源、估算性质和不确定性。它们不能表述为诊断、处方或医学结论。
- 不要求用户填写身高、体重、疾病、药物等敏感信息才能完成基础记录。若未来增加目标资料，必须单独定义最小化采集、访问授权和删除规则。
- 儿童端默认没有健康模块。任何面向儿童的运动功能必须独立设计年龄适配、监护和隐私范围后再启用。
- 趋势图不得因为数据缺失、来源不明或导入失败而推断“改善”或“恶化”；应展示覆盖天数和数据缺口。
- AI 或外部估算生成的食材候选、份量和营养值在用户确认前只属于草稿，不写入正式餐食记录。

## 5. 验收标准

| 编号          | 验收场景                                                                                                     |
| ------------- | ------------------------------------------------------------------------------------------------------------ |
| AC-HEALTH-001 | 成人创建包含类型、时间和时长的运动记录后，本人趋势与工作台数据在相同统计范围内一致。                         |
| AC-HEALTH-002 | 负时长、结束早于开始、无效单位和无权成员 ID 的运动请求均被服务端拒绝，并返回字段级或操作级反馈。             |
| AC-HEALTH-003 | 成人录入一餐并人工修正热量后，详情同时展示原始来源、估算/修正状态和最终数值。                                |
| AC-HEALTH-004 | 家长在无共享授权时，不能通过列表、详情、工作台、搜索或导出获得成人的任何健康记录；授权和撤销后结果立即变化。 |
| AC-HEALTH-005 | 用户重复导入同一份已确认文件时，系统在预览或确认阶段提示重复并避免新增重复记录。                             |
| AC-HEALTH-006 | 健康趋势在记录为空、数据来源不完整或统计范围变更时，展示相应空状态或覆盖说明，不生成医疗化结论。             |
