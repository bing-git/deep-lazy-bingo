# 知识库与学习 AI 交付切片

## 1. 目的

本文件把 `FR-KB-*`、`FR-LAI-*`、`FR-AI-*` 与相关非功能需求拆成可独立验证的纵向切片。它不引入新的产品需求 ID，而是规定实现顺序、依赖、完成定义与决策门槛，避免先堆积大量页面、表或模型调用后才发现权限、来源、向量维度或审核链路不成立。

全项目的非 AI 前置、健康/服务独立验收及本切片的依赖衔接见[分阶段实现与验证方案](../architecture/05-phased-delivery-plan.md)。该方案不改变本文件 K0–K7 编号或原始 P0/P1；基础学习闭环不等于知识库首闭环，也不等于全项目 P0 完成。

## 2. 首个可用闭环

```text
家长创建儿童知识库空间
  -> 声明一份可用来源并上传一份授权资料
  -> 后端解析、分块、生成 Embedding、写入 pgvector
  -> 儿童从被分配任务发起一个资料问答
  -> 系统只检索儿童有权资料并显示引用
  -> 家长可查看草稿/引用，儿童不能看到管理与技术信息
```

在这个闭环之前，不做多模态、跨空间自动检索、复杂评测控制台、口语、外部连接器或大规模重索引优化。

## 3. 交付切片

| 切片                   | 目标                                     | 主要需求                                                               | 最小交付物                                                               | 完成定义                                                         |
| ---------------------- | ---------------------------------------- | ---------------------------------------------------------------------- | ------------------------------------------------------------------------ | ---------------------------------------------------------------- |
| K0：工程与能力门槛     | 验证运行环境与安全基线                   | `FR-KB-060`、`FR-AI-001`、`NFR-DATA-*`、`NFR-SEC-*`                    | Spring Boot/数据库基线、Flyway、pgvector 扩展检查、AI 开关、OpenAPI 骨架 | 空数据库能迁移；扩展缺失时知识库安全不可用；普通业务不受阻断。   |
| K1：空间、来源与文档   | 建立授权资料的真实生命周期               | `FR-KB-001` 至 `026`、`FR-IAM-030` 至 `034`                            | 空间/来源/文档/版本 API、受控上传、列表与详情页面、审计事件              | 跨家庭/跨成员访问被拒绝；来源/归档状态真实生效。                 |
| K2：摄取与向量         | 将一份资料转成可检索的版本化证据         | `FR-KB-030` 至 `075`、`NFR-PERF-002`                                   | 摄取 worker、解析器、分块、Embedding 适配器、pgvector 表/索引、任务中心  | 相同版本幂等；失败可见/可重试；维度错误/来源失效不会标为可检索。 |
| K3：受控检索与引用     | 实现权限安全的资料召回                   | `FR-KB-080` 至 `105`                                                   | SQL 内 ACL 过滤、向量/全文混合候选、引用 DTO、检索检查器                 | 撤销后立即无命中；无资料不伪造引用；有权用户能回到版本/定位。    |
| K4：学习 AI 问答与讲解 | 让学习者获得可审核的引用回答             | `FR-LAI-001` 至 `016`、`FR-LAI-060` 至 `073`                           | 任务编排、上下文预算、5.6-Terra Max 适配器、schema 校验、会话/草稿页面   | AI 关闭/超时/无资料有可恢复状态；儿童只看到适龄、授权证据。      |
| K5：练习与错题辅导     | 形成“错误 -> 辅导 -> 审核 -> 复习”的闭环 | `FR-LAI-020` 至 `036`、`FR-LEARN-020` 至 `026`                         | 错题辅导、练习生成、审核/采纳、复习任务关联                              | 题目未校验/未采纳不可发布；尝试历史和提示均可追溯。              |
| K6：英语与学习路径     | 扩展成人/获授权儿童学习场景              | `FR-LAI-040` 至 `053`                                                  | 英语工坊、词汇/理解练习、学习路径和反思草稿                              | 文章事实有引用，生成任务可选择性采纳，不自动创建大量任务。       |
| K7：质量与发布         | 让系统可观测、可评测、可恢复             | `FR-KB-120` 至 `126`、`FR-LAI-074` 至 `076`、`NFR-TEST-*`、`NFR-OPS-*` | 评测集、基准、指标、备份/恢复、E2E、发布门禁                             | 质量回归阻止默认升级；权限/注入/撤销负向测试自动化通过。         |

## 4. 每个切片的必做检查

| 维度 | 必做检查                                                                            |
| ---- | ----------------------------------------------------------------------------------- |
| 权限 | 家长、成人、儿童、跨家庭和授权撤销后五类调用均有正/负向测试。                       |
| 数据 | 新表经 Flyway 创建；版本、幂等、归档和清理状态可解释；不修改旧迁移。                |
| API  | 请求/响应/错误/分页/幂等进入 OpenAPI；前端使用生成类型或类型校验。                  |
| 前端 | 桌面与窄屏有加载、空、失败、无权、过期和完成状态；关键操作不依赖 hover。            |
| AI   | 输入最小化、来源/引用、schema、超时、取消、AI 关闭降级和审计均可验证。              |
| 安全 | 无秘密、无真实儿童/健康资料、无任意 URL/命令工具；检索在 SQL/服务层进行 ACL 过滤。  |
| 验证 | 记录实际命令、人工验收结果、失败和残余风险，并关联对应需求 ID。 |

## 5. 决策门槛

| 门槛     | 必须确认后才进入下一切片                                                         |
| -------- | -------------------------------------------------------------------------------- |
| K0 -> K1 | 部署 PostgreSQL/pgvector 版本、扩展启用方式、基础存储策略与家庭隔离测试可用。    |
| K1 -> K2 | 来源许可、上传类型/大小、对象存储、病毒/内容扫描和保留策略已确定。               |
| K2 -> K3 | Embedding 提供商、模型 ID、向量维度、费用/额度、重试与数据驻留已确认。           |
| K3 -> K4 | 检索评测集、引用展示、无资料/冲突来源状态和撤销授权测试通过。                    |
| K4 -> K5 | 5.6-Terra Max 实际能力矩阵、结构化输出、儿童内容规则、草稿审核和用量策略已验证。 |
| K5 -> K6 | 练习 schema、采纳流程、错题/任务关联与家长审核体验已完成端到端验证。             |
| K6 -> K7 | 目标规模、性能基准、备份恢复、监控告警和发布流程已落地。                         |

## 6. 不得跳过的风险

- 不能先做“聊天页面”，后补来源、空间、版本和撤销授权。
- 不能先建全局向量索引，再把权限过滤留给前端/Java 内存。
- 不能因为模型支持 1M token 就把全文资料、完整会话或全家数据送入一个请求。
- 不能让 AI 草稿绕过学习内容、题目、任务和审核的领域规则。
- 不能以 REA 观察商业版页面替代本项目的独立设计、许可证审查或 E2E 验收。
