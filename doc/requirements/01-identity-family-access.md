# 账号、家庭与访问控制需求

## 1. 范围

本模块定义登录主体、家庭空间、成员档案、角色、会话、对象级授权和数据共享授权。它为学习、健康、家庭服务、AI 草稿和管理模块提供统一的身份与权限判断，不直接承载具体业务内容。

## 2. 核心对象

| 对象     | 必需业务属性                                         | 说明                                               |
| -------- | ---------------------------------------------------- | -------------------------------------------------- |
| 账号     | 唯一标识、登录名或邮箱、密码凭据、状态、最后登录时间 | 可登录的安全主体；密码只能以强哈希保存。           |
| 家庭空间 | 唯一标识、显示名称、时区、状态、创建人               | 数据与授权的首要隔离边界。                         |
| 成员档案 | 家庭空间、显示名称、成员类型、关联账号、状态         | 儿童可没有可登录账号；敏感资料应最小化保存。       |
| 家庭角色 | 家长、成人、儿童                                     | 描述成员在当前家庭内的默认能力，而非系统超级权限。 |
| 授权记录 | 授权人、被授权人、数据范围、有效状态、创建/撤销时间  | 用于健康数据、AI 汇总等超出默认可见范围的访问。    |
| 会话     | 账号、设备摘要、签发/过期/失效时间、刷新状态         | 用于安全的登录态维持和会话撤销。                   |

## 3. 功能需求

### 3.1 账号与会话

| ID         | 优先级 | 需求                                                                                                                                         |
| ---------- | ------ | -------------------------------------------------------------------------------------------------------------------------------------------- |
| FR-IAM-001 | P0     | 系统必须允许成人使用已注册且启用的账号登录，并在验证成功后建立会话。登录失败仅返回通用错误，不能透露账号是否存在、是否被锁定或密码是否正确。 |
| FR-IAM-002 | P0     | 系统必须对登录、密码重置和绑定类操作施加基于账号标识、IP 与时间窗口的速率限制，并记录可审计的安全事件。                                      |
| FR-IAM-003 | P0     | 已登录账号必须能够主动退出当前会话；退出后该会话不能再访问受保护 API。                                                                       |
| FR-IAM-004 | P0     | 受保护 API 必须拒绝缺少、过期、失效或篡改的会话凭据，并返回统一的未认证错误。                                                                |
| FR-IAM-005 | P1     | 账号必须能够查看并撤销自己的其他活跃会话；撤销后目标会话在下一次请求时失效。                                                                 |
| FR-IAM-006 | P1     | 系统必须提供密码重置流程。重置令牌必须一次性、短时有效，且不得写入审计明文、日志或前端持久化存储。                                           |
| FR-IAM-007 | P2     | 系统可支持未来的微信身份绑定和解绑；微信临时 `code`、平台凭据与平台会话必须严格分离。                                                        |

### 3.2 家庭与成员

| ID         | 优先级 | 需求                                                                                                 |
| ---------- | ------ | ---------------------------------------------------------------------------------------------------- |
| FR-IAM-010 | P0     | 首位创建者必须能够创建一个家庭空间，并以家长身份加入；家庭名称和时区可在授权范围内维护。             |
| FR-IAM-011 | P0     | 家长必须能够创建儿童成员档案，设置显示名称和必要的学习识别信息；儿童档案默认不具备登录能力。         |
| FR-IAM-012 | P0     | 家长必须能够更新或停用自己家庭内的成员档案。停用成员后，系统保留历史记录并停止其后续访问和任务分配。 |
| FR-IAM-013 | P1     | 家长必须能够邀请成人加入家庭；邀请接受前不得暴露家庭成员、学习、健康或服务目录数据。                 |
| FR-IAM-014 | P1     | 成人成员必须能够离开家庭空间；离开不得删除其本人历史记录，且需按数据保留规则处理共享关系。           |
| FR-IAM-015 | P1     | 家长必须能够为儿童创建或停用独立登录方式；启用前需确认儿童档案与登录账号的绑定关系。                 |
| FR-IAM-016 | P1     | 系统必须支持成员的显示名称和头像等非安全资料；头像上传属于受控文件上传，不能作为任意文件存储入口。   |

### 3.3 默认角色能力

| ID         | 优先级 | 需求                                                                                                                           |
| ---------- | ------ | ------------------------------------------------------------------------------------------------------------------------------ |
| FR-IAM-020 | P0     | 家长可管理本家庭的儿童成员、儿童学习计划、学习内容分配、家庭服务目录和家庭级设置。                                             |
| FR-IAM-021 | P0     | 成人可查看和维护自己的学习、运动、餐食、个人偏好和本人创建的 AI 草稿。                                                         |
| FR-IAM-022 | P0     | 儿童只能访问分配给自己的学习任务、允许查看的学习记录和个人基础进度；不能读取成人健康数据、服务配置、权限或其他成员的私有记录。 |
| FR-IAM-023 | P0     | 家长对成人成员的健康和个人学习数据不具有默认读取权；只有存在有效、明确的数据范围授权时才可访问。                               |
| FR-IAM-024 | P0     | 角色改变、成员停用和授权撤销必须在后续请求中立即生效；缓存不得使已撤销权限继续有效。                                           |
| FR-IAM-025 | P1     | 系统可支持家庭内更细粒度的委托能力，但不得以“成人”这一大角色自动授予全部管理能力。                                             |

### 3.4 对象级授权与共享

| ID         | 优先级 | 需求                                                                                                                              |
| ---------- | ------ | --------------------------------------------------------------------------------------------------------------------------------- |
| FR-IAM-030 | P0     | 每次读取、创建、修改、删除、搜索、导出和附件访问都必须验证当前账号、家庭空间、当前成员身份和目标对象之间的关系。                  |
| FR-IAM-031 | P0     | 无权访问资源时，系统必须返回与“资源不存在”一致的安全响应，且不返回资源名称、成员姓名、记录数量或其他存在性线索。                  |
| FR-IAM-032 | P0     | 所有业务对象必须携带可验证的家庭归属；成员私有对象还必须携带所属成员。禁止仅依赖客户端提交的家庭或成员 ID 决定可访问范围。        |
| FR-IAM-033 | P0     | 健康数据、AI 汇总和其他敏感跨成员数据必须通过独立授权记录开放；授权至少说明数据类别、被授权成员、用途或范围、授予时间和撤销状态。 |
| FR-IAM-034 | P0     | 授权人必须能够随时撤销自己授予的数据访问；撤销不删除历史审计，但应阻断未来访问和未来 AI 输入组装。                                |
| FR-IAM-035 | P1     | 家长必须能查看儿童学习数据的访问记录摘要；成人必须能查看自己健康数据被共享的当前授权。                                            |

## 4. 关键业务规则

- 一个请求只在一个活动家庭空间上下文中执行。若账号未来属于多个家庭，切换必须显式完成，不能从 URL 或上一请求隐式继承。
- 账号关联成员档案不等于拥有该成员的所有数据；权限由当前家庭角色和授权记录共同决定。
- 儿童姓名、生日、健康与学习数据属于敏感个人信息。接口、日志、错误信息、通知标题和搜索摘要都必须最小化披露。
- 删除成员、家庭或账号属于高风险操作。P0 阶段可只支持停用；永久删除必须另行定义数据保留、导出和恢复流程后才可开放。
- 系统管理员的运维权限和家庭数据访问权限必须分离；任何紧急数据访问应走受控、可审计流程。

## 5. 验收标准

| 编号       | 验收场景                                                                                                              |
| ---------- | --------------------------------------------------------------------------------------------------------------------- |
| AC-IAM-001 | 未登录用户调用任一受保护业务 API 时得到统一未认证响应，响应不包含堆栈、SQL、成员或家庭数据。                          |
| AC-IAM-002 | 家长 A 能创建儿童 C 的档案与学习任务；家庭 B 的家长和成员无法通过列表、详情、搜索或猜测 ID 获取 C 的数据。            |
| AC-IAM-003 | 成人 A 的健康记录默认不出现在家长或另一成人的列表、首页、搜索和导出中；A 授权后，仅被授权范围可见，撤销后立即不可见。 |
| AC-IAM-004 | 儿童 C 登录后只能看到自己的学习页面与任务，直接访问 `/admin`、健康和其他成员的学习 URL 均被拒绝或重定向到无权页面。   |
| AC-IAM-005 | 连续错误登录达到配置阈值时系统限制后续尝试并记录安全事件；正确凭据的正常登录不泄露锁定实现细节。                      |
| AC-IAM-006 | 退出或撤销某会话后，该会话再次调用 API 失败，而同一账号未撤销的其他会话按策略保持有效。                               |
