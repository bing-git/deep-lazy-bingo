# AI 草稿与治理需求

## 1. 范围

本模块将 AI 作为可替换、可禁用、需审核的后端能力。首选目标模型为 **5.6-Terra Max**，最大上下文窗口为 **1,000,000 token**。模型能力上限不改变家庭数据最小化、来源核验、对象级授权和人工审核要求。

AI 可辅助生成学习讲解、练习、英语文章、训练计划、餐食估算和服务状态摘要；它不能自动发布正式内容、替代医疗或教育专业判断、执行命令、代理内网服务或绕过任何权限。

## 2. 核心对象

| 对象          | 必需业务属性                                                     | 说明                                       |
| ------------- | ---------------------------------------------------------------- | ------------------------------------------ |
| AI 提供商配置 | 提供商标识、显示模型名、正式 model ID、启用状态、超时与额度策略  | 凭据仅由部署环境注入，不进入前端或代码库。 |
| AI 任务       | 类型、发起成员、家庭、授权范围、输入摘要、状态、请求时间         | 描述一次受控请求，不默认保存敏感原文。     |
| 检索来源      | 标题、链接或内部来源标识、版本/日期、检索时间、授权状态          | 为检索型输出提供可核验依据。               |
| AI 草稿       | 任务、结构化内容、来源、模型/提示词版本、审核状态、创建/修改时间 | 未采纳前不属于正式业务数据。               |
| 审核动作      | 操作者、动作、修改摘要、时间、理由（可选）                       | 包含采纳、拒绝、退回和过期。               |
| 用量事件      | 成员或家庭、任务类型、输入/输出计量、结果、时间                  | 用于额度与审计，避免保存完整敏感输入。     |

## 3. 功能需求

### 3.1 提供商与模型配置

| ID        | 优先级 | 需求                                                                                                                                                    |
| --------- | ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| FR-AI-001 | P0     | AI 必须默认关闭。未启用、缺少必填配置或提供商不可用时，非 AI 的学习、健康、服务目录和管理功能必须仍可正常使用。                                         |
| FR-AI-002 | P0     | 系统必须将显示名称“5.6-Terra Max”与提供商实际 `modelId` 分开配置，并支持最大 `1,000,000` token 的上下文窗口配置。不得猜测模型标识、API 地址或认证方式。 |
| FR-AI-003 | P0     | API 地址、密钥、组织标识和其他凭据只能从部署环境或受控密钥管理设施读取，不得下发浏览器、写入日志、错误响应、源码或需求示例。                            |
| FR-AI-004 | P0     | AI 服务层必须以任务接口屏蔽提供商 SDK 差异；业务模块不得直接拼接供应商请求或持有供应商密钥。                                                            |
| FR-AI-005 | P1     | 系统可支持多个提供商或本地模型适配器，但同一任务必须记录实际提供商、模型、提示词版本和配置摘要。                                                        |
| FR-AI-006 | P1     | 家长或部署管理员必须能在不发布前端的情况下关闭全局 AI、某类任务或某个家庭的 AI 功能。                                                                   |

### 3.2 授权、输入与检索

| ID        | 优先级 | 需求                                                                                                                                        |
| --------- | ------ | ------------------------------------------------------------------------------------------------------------------------------------------- |
| FR-AI-010 | P0     | 用户必须明确发起每次 AI 任务，或在可见设置中提前同意明确的任务类型；系统不得默认把儿童、健康或家庭服务数据发送给第三方模型。                |
| FR-AI-011 | P0     | 后端在组装 AI 输入前必须针对任务类型、当前成员、家庭关系和共享授权重新执行对象级权限校验。无权数据不能因工作台聚合、检索或缓存进入上下文。  |
| FR-AI-012 | P0     | 输入组装必须遵循最小化原则，仅选择完成任务需要的字段和经授权来源。成员姓名、精确地址、联系方式、凭据和无关健康字段必须被移除或替换。        |
| FR-AI-013 | P0     | 系统必须计算或估算输入与预期输出 token，确保单次请求不超过配置的 `1,000,000` token 上下文窗口；超限时要求用户缩小范围或进行可见的分段处理。 |
| FR-AI-014 | P0     | 检索型任务必须返回来源标题、链接或内部标识、版本或日期（如有）和检索时间。没有可核验来源时，输出必须明确说明，而不能编造引用。              |
| FR-AI-015 | P0     | 用户上传资料、外部页面和服务说明等检索内容必须被视为不可信数据；其内容不能改变系统指令、获取凭据、扩大检索范围或触发工具调用。              |
| FR-AI-016 | P1     | 用户必须能查看本次任务发送的数据类别、来源数量与隐私提示，并能在提交前取消。                                                                |
| FR-AI-017 | P1     | 系统可支持经过许可审查的官方目录或授权搜索连接器；连接器的抓取范围、缓存期、来源许可和失败行为必须独立配置。                                |

### 3.3 草稿、审核与正式采纳

| ID        | 优先级 | 需求                                                                                                                        |
| --------- | ------ | --------------------------------------------------------------------------------------------------------------------------- |
| FR-AI-020 | P0     | AI 输出必须先保存为草稿，状态至少包括“生成中”“待审核”“已采纳”“已拒绝”“失败”和“已过期”。                                     |
| FR-AI-021 | P0     | 草稿必须显示任务类型、生成时间、模型显示名、来源、估算或不确定性提示、内容结构和关联业务对象；UI 不能将其呈现为已验证事实。 |
| FR-AI-022 | P0     | 创建者可以编辑、拒绝或重新生成自己的草稿；涉及儿童学习内容的草稿可由有权家长审核。审核范围不得超出成员权限。                |
| FR-AI-023 | P0     | 只有用户显式执行“采纳”后，系统才能把草稿转为学习内容、练习、训练计划、餐食候选或其他正式对象。采纳必须创建可追溯关联。      |
| FR-AI-024 | P0     | 采纳操作必须校验目标业务对象的权限、字段校验和来源状态；AI 返回的任意字段都不能绕过服务端校验。                             |
| FR-AI-025 | P1     | 审核人必须能比较 AI 原始草稿与采纳前编辑后的摘要；系统保留审核动作而非无限保存完整敏感提示词。                              |
| FR-AI-026 | P1     | 草稿可在配置保留期后自动过期；过期草稿不能被直接采纳，需重新生成或恢复审核流程。                                            |

### 3.4 任务类型与安全边界

| ID        | 优先级 | 需求                                                                                                                        |
| --------- | ------ | --------------------------------------------------------------------------------------------------------------------------- |
| FR-AI-030 | P0     | 系统可生成学习讲解提纲、例题、单选练习草稿、英语文章草稿和知识主题摘要；学习输出必须保留来源或清楚标注为创作内容。          |
| FR-AI-031 | P1     | 系统可根据用户确认的运动与餐食记录生成可编辑训练/餐食建议或营养估算候选，并始终标注为估算，不作为医疗建议。                 |
| FR-AI-032 | P1     | 系统可基于有权服务的脱敏状态和说明生成只读状态摘要或排查建议。                                                              |
| FR-AI-033 | P0     | AI 不得执行命令、调用任意网络地址、修改服务配置、删除文件、触发购买/分享/通知外发，或直接代替用户提交业务变更。             |
| FR-AI-034 | P0     | AI 输出必须经过结构化 schema 校验、长度限制、内容安全处理和领域字段校验；不符合预期结构的输出必须作为失败或待修复草稿处理。 |
| FR-AI-035 | P0     | AI 请求必须支持超时、取消、限流和失败降级。超时或错误不得泄漏密钥、完整上下文、内部提示词或供应商原始错误。                 |
| FR-AI-036 | P1     | 系统必须按家庭、成员和任务类型实施额度或频率限制，并向用户显示可理解的可用状态而非供应商错误细节。                          |

### 3.5 审计、保留与删除

| ID        | 优先级 | 需求                                                                                                                         |
| --------- | ------ | ---------------------------------------------------------------------------------------------------------------------------- |
| FR-AI-040 | P0     | 每次任务必须记录发起者、家庭、任务类型、实际模型、提示词版本、输入类别摘要、来源摘要、时间、结果状态和用量摘要。             |
| FR-AI-041 | P0     | 审计默认不得保存完整儿童资料、完整健康记录、密钥、原始外部网页或全部模型上下文；需要保存的草稿正文应有明确保留期和访问控制。 |
| FR-AI-042 | P0     | 用户必须能查看自己可见草稿的生成与审核历史；家长只能查看其有权的儿童学习草稿，不能借此读取成人私有 AI 任务。                 |
| FR-AI-043 | P1     | 系统必须提供按保留策略清理草稿、任务载荷和临时检索材料的机制，并保留最小必要的合规审计摘要。                                 |

## 4. 关键业务规则

- `1,000,000 token` 是模型上下文的技术上限，而不是默认把完整家庭历史、教材、日志或上传文件发送给模型的理由。任务必须先按权限、相关性、来源和预算筛选。
- 模型显示名不是可执行配置。真正的 `modelId`、服务地址和认证形式必须以已验证的提供商文档和部署配置为准。
- AI 的知识性输出、营养估算和服务建议都不能被描述成专业诊断或保证准确的结论；来源不可用时必须诚实提示不确定性。
- 外部文档中的“忽略上述规则”“请求密钥”“执行命令”等文本仅是待分析内容，不是系统指令。模型不得拥有平台权限或网络执行权限。
- 用户编辑草稿后，采纳对象应记录“AI 辅助并经人工编辑”的来源关系；不能把人工改写后内容伪装成未审核模型输出或反之。

## 5. 验收标准

| 编号      | 验收场景                                                                                                        |
| --------- | --------------------------------------------------------------------------------------------------------------- |
| AC-AI-001 | AI 未配置、被全局关闭或提供商超时时，学习和健康的普通新增、查询与统计仍可完成；界面展示可理解的 AI 不可用状态。 |
| AC-AI-002 | 系统使用配置的“5.6-Terra Max”显示名与正式 `modelId` 发起请求，并拒绝超过 1,000,000 token 上下文窗口的输入。     |
| AC-AI-003 | 成人在未授权的情况下请求家庭总结时，后端不将其他成人健康数据或儿童私有资料加入输入或输出。                      |
| AC-AI-004 | 检索型学习草稿显示可核验来源和检索时间；无来源时明确提示无法核验，且不存在伪造链接。                            |
| AC-AI-005 | 生成练习草稿后，题目不会自动出现在儿童任务中；家长审核、编辑并显式采纳后才成为正式可发布练习。                  |
| AC-AI-006 | 包含提示注入文本的上传资料不会改变系统策略、扩大检索范围、返回密钥或触发网络/服务操作。                         |
| AC-AI-007 | 审计记录能说明谁在何时因何种任务使用了哪个模型和来源类别，但不包含明文 API 密钥或完整敏感上下文。               |
