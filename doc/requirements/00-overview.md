# 需求总览与约定

## 1. 文档目的

本目录将家庭学习与生活管理平台拆分为可实现、可测试、可追踪的需求，定义“系统必须做什么”，不替代数据库、接口、组件或部署设计。技术方案见[架构文档](../architecture/README.md)；需求与架构冲突时，以经确认的需求基线为准。

## 2. 产品范围

平台服务一个默认私有家庭空间，统一支持：

- 家长安排和跟进儿童学习；
- 成人管理个人学习、运动和饮食；
- 以受控知识库、PostgreSQL/pgvector 检索和审核制学习 AI 辅助学习；
- 家庭成员访问经过登记的内网服务；
- 以审核制 AI 草稿辅助学习、健康和家庭信息整理；
- 通过 PC Web 提供日常工作台和家庭管理入口，并为未来微信小程序复用 API。

首期不提供微服务拆分、任意内网代理或命令执行、未经审核的 AI 自动发布、完整教材分发、医疗诊断、华为手表直连，也不承诺微信小程序已经可用。

## 3. 角色与权限术语

| 角色   | 定义                             | 默认能力                                                                   |
| ------ | -------------------------------- | -------------------------------------------------------------------------- |
| 家长   | 家庭空间的管理成人               | 管理家庭成员、儿童学习计划、家庭服务和授权范围；查看被明确授权的健康信息。 |
| 成人   | 独立的家庭成年成员               | 管理自己的学习、健康记录和个人偏好；可按授权查看共享数据。                 |
| 儿童   | 由家长创建或管理的未成年人档案   | 查看和完成分配给自己的学习任务；不管理家庭配置。                           |
| 管理员 | 在系统级部署中维护平台的受限角色 | 不因技术角色自动拥有家庭私密数据；其数据访问必须可审计且受单独策略约束。   |

“账号”是可登录主体；“成员档案”是家庭内的数据主体；一个账号可关联一个或多个允许的成员身份，但每次请求都必须解析当前家庭上下文和成员权限。

## 4. 优先级与状态

| 标记     | 含义                                                 |
| -------- | ---------------------------------------------------- |
| `P0`     | 首个可用闭环所必需；缺失则不能交付该阶段。           |
| `P1`     | 首期后优先实现；不阻断 P0 主路径。                   |
| `P2`     | 验证真实使用后再排期。                               |
| `待确认` | 信息不足，不能据此直接编码；需记录责任人和决定日期。 |

每条功能需求使用 `FR-<模块>-<序号>` 编号；非功能需求使用 `NFR-<分类>-<序号>` 编号。需求状态在实施看板管理，不在本文档中用“已完成”替代测试证据。

## 5. 统一业务规则

- **家庭隔离**：任何业务对象都属于一个家庭或可验证的成员主体。跨家庭读取、修改、搜索、导出和附件访问必须被服务端拒绝。
- **对象级授权**：前端隐藏菜单不是授权。后端必须在读取、写入、导出、搜索和 AI 输入组装时验证当前主体对目标对象的权限。
- **最小披露**：列表、通知、搜索和仪表盘只返回完成当前任务所需字段；儿童、健康、服务地址和凭据按敏感数据处理。
- **可追溯修改**：会改变计划、内容、权限、服务配置或 AI 草稿状态的操作，记录操作者、时间、对象、前后摘要和结果。
- **可恢复失败**：网络、模型或外部服务失败时，系统给出明确状态与重试方式；基础记录和查询功能不能依赖 AI 可用。
- **时间与时区**：服务端存储 UTC 时间戳；界面按家庭配置的时区显示日期、日程与趋势边界。

## 6. 通用验收规则

除非某条需求另有说明，以下标准同时适用：

1. 合法主体可完成操作并获得明确的成功、空、加载或失败反馈。
2. 无权主体以统一的安全错误响应被拒绝，响应不泄漏目标对象是否存在。
3. 输入在客户端辅助校验、服务端强制校验；错误定位到字段或操作级别。
4. 成功写操作在刷新页面后保持一致，且不会产生重复记录。
5. 关键路径可在桌面和移动浏览器完成；不以仅 hover 的控件承载必要动作。
6. 每条 `P0` 需求至少有一个自动化测试层级：单元、集成或端到端，具体层级按风险确定。

## 7. 术语

| 术语       | 定义                                                             |
| ---------- | ---------------------------------------------------------------- |
| 家庭空间   | 同一家庭成员、数据对象、设置和授权关系的隔离边界。               |
| 学习计划   | 针对一个成员、一个期限和一组学习目标的可执行安排。               |
| 学习任务   | 从学习计划派生、可在某天完成的最小行动项。                       |
| 内容条目   | 知识点、讲解、笔记、阅读材料或练习题等受控内容。                 |
| 记录       | 对学习、练习、运动或餐食等真实发生事件的不可随意覆盖的事实数据。 |
| AI 草稿    | 由模型生成、尚未被人工采纳到正式业务对象的内容。                 |
| 来源       | 内容、营养数值或 AI 检索结果的可核验出处及其版本/日期。          |
| 知识库空间 | 在家庭与成员授权范围内组织可检索资料、来源和版本的容器。         |
| 文档版本   | 一次不可原地覆盖的资料内容快照，分块、Embedding 和引用均依附它。 |
| Embedding  | 按模型/维度版本生成的分块派生向量，只用于受权限控制的语义检索。  |
| 引用       | AI 草稿与其文档版本/分块/源定位之间的可核验关联。                |

## 8. 需求追踪最小字段

每个功能模块至少明确以下内容：目标角色、前置条件、正常流程、异常/边界规则、权限约束、数据保留或来源要求、验收标准，以及依赖的其他模块。API 和数据库设计完成后，应把需求 ID 标注到 OpenAPI operation、迁移说明和自动化测试名称或测试说明中。
