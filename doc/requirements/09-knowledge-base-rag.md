# 知识库与检索增强生成需求

## 1. 范围

本模块为学习 AI 提供受控、可追溯、可撤销的知识基础。它接收家庭成员有权使用的学习资料、个人笔记、授权资源元数据和经过确认的 AI 辅助内容，将其版本化、解析、分块、向量化并保存到 PostgreSQL 的 pgvector 索引中；检索结果再作为学习问答、讲解、练习、复习与学习路径草稿的证据来源。

知识库不是文件网盘、公开教材镜像、通用搜索引擎或模型训练数据池。未获授权的教材全文、扫描件、题库和第三方网页不能被默认抓取、长期保存、嵌入或分发。AI 生成文本在被人工采纳前也不自动成为可信知识来源。

## 2. 关键概念与对象

| 对象       | 必需业务属性                                                       | 说明                                                             |
| ---------- | ------------------------------------------------------------------ | ---------------------------------------------------------------- |
| 知识库空间 | 家庭、名称、用途、可见范围、状态、创建者                           | 检索与资料隔离的容器，例如“儿童数学”“成人英语”或“家庭自建笔记”。 |
| 来源       | 类型、标题、许可/授权状态、作者或发布者、链接、版本/日期、来源声明 | 说明资料为何可以使用、如何核验和何时需要复核。                   |
| 知识文档   | 知识库空间、来源、逻辑标题、内容类型、可见范围、状态               | 用户可理解的资料对象，不等同于某个物理上传文件。                 |
| 文档版本   | 文档、版本号、内容摘要、原始媒介引用、解析状态、创建时间           | 一次稳定内容快照；已索引版本不可被原地覆盖。                     |
| 分块       | 文档版本、顺序、标题路径、文本、源定位、token 数、可见范围         | 可检索的最小证据单元，保留回到原文的定位能力。                   |
| Embedding  | 分块、模型标识、维度、向量、生成时间、状态                         | 用于语义相似度检索的派生数据，不是原始资料的替代品。             |
| 摄取任务   | 请求者、目标版本、步骤、状态、错误摘要、幂等键、时间               | 解析、分块、向量化和索引的可观察异步工作流。                     |
| 检索会话   | 发起成员、任务类型、查询摘要、授权快照、时间、结果状态             | 审计一次检索，但默认不保存完整敏感问题或全部上下文。             |
| 检索命中   | 会话、分块、排序分数、重排分数、采用状态                           | 说明生成或回答实际使用了哪些授权证据。                           |
| 引用       | 输出草稿、文档版本、分块、显示标签、源定位                         | 让用户从 AI 输出跳回可核验资料。                                 |

## 3. 知识库空间、来源与文档生命周期

### 3.1 知识库空间

| ID        | 优先级 | 需求                                                                                                                                               |
| --------- | ------ | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| FR-KB-001 | P0     | 家长和成人必须能在有权家庭范围内创建、查看、修改、归档知识库空间；儿童默认只能使用明确分配给自己的空间，不能管理空间配置。                         |
| FR-KB-002 | P0     | 知识库空间必须至少保存家庭归属、名称、用途、默认可见范围、状态、创建者和创建时间。名称在同一家庭内应可辨识，但不应向无权成员的搜索或错误响应泄漏。 |
| FR-KB-003 | P0     | 空间可见范围必须支持“仅创建者”“明确成员”“家长管理的儿童”“家庭成人”或等价的最小权限表达；检索、浏览、摄取、导出和 AI 输入均分别检查权限。           |
| FR-KB-004 | P0     | 归档知识库空间后，系统停止新资料摄取、重新索引和新的 AI 检索；历史草稿、引用和学习记录仍应保留可理解的空间名称与归档状态。                         |
| FR-KB-005 | P1     | 家长可为儿童学习空间指定可使用的内容类型、成人审核要求和资料上传权限；儿童不能将资料共享到家庭成人空间。                                           |
| FR-KB-006 | P1     | 系统可为同一家庭建立多个用途明确的空间，但跨空间检索必须由用户显式选择或由已记录的任务策略决定，不能默认把所有家庭资料混合。                       |

### 3.2 来源与许可

| ID        | 优先级 | 需求                                                                                                                                                 |
| --------- | ------ | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| FR-KB-010 | P0     | 每个可检索文档必须关联来源记录，来源至少包含类型、标题或说明、创建/发布者（如有）、链接或内部来源标识、版本或日期（如有）、记录时间和许可/授权状态。 |
| FR-KB-011 | P0     | 来源状态至少区分“用户自建”“用户确认可用”“已授权”“待核验”“不允许检索”“已失效”；处于待核验、不允许检索或已失效状态的版本不得进入新的 AI 检索结果。     |
| FR-KB-012 | P0     | 用户上传或录入资料时，系统必须要求选择来源类型和授权声明；无法确认版权或使用范围时，只能保存最小元数据或草稿，不得自动向成员分发全文或生成检索索引。 |
| FR-KB-013 | P1     | 系统可保存来源复核日期、复核人、许可摘要和失效原因，以便家长或成人在来源发生变化时重新决定是否继续检索。                                             |
| FR-KB-014 | P1     | 外部网页、目录或连接器返回的内容必须保留抓取/检索时间、来源 URL、版本线索和使用许可判断；连接器不得跨越站点条款、访问控制或 robots/授权边界。        |
| FR-KB-015 | P1     | 当来源被标记为不允许检索或失效时，系统必须在后续检索、生成、导出和新的任务分配中排除其分块；历史 AI 草稿保持引用但显示来源已失效。                   |

### 3.3 文档与版本

| ID        | 优先级 | 需求                                                                                                                                         |
| --------- | ------ | -------------------------------------------------------------------------------------------------------------------------------------------- |
| FR-KB-020 | P0     | 家长和成人必须能创建知识文档，或将经授权上传资料、个人笔记、学习内容条目导入为文档；文档必须绑定知识库空间、来源、内容类型、可见范围和状态。 |
| FR-KB-021 | P0     | 每次内容实质修改、重新上传或重新抓取必须创建新的文档版本；已经用于检索、AI 草稿、练习或学习记录的版本不可原地改写。                          |
| FR-KB-022 | P0     | 文档版本必须保存内容摘要或不可变校验标识、媒介类型、解析状态、创建者、创建时间和父版本关系，以支持重试、审计和引用解释。                     |
| FR-KB-023 | P0     | 文档、版本和分块的可见范围不得比所属知识库空间更宽；缩小空间或文档范围后，受影响版本必须立即从后续检索候选中排除。                           |
| FR-KB-024 | P0     | 用户必须能归档文档或特定版本。归档后不得产生新的分块、Embedding 或检索命中；已有引用不应变成无标题或无法解释的断链。                         |
| FR-KB-025 | P1     | 文档列表必须展示版本数、当前可检索版本、解析/索引状态、来源状态、最后处理时间和错误摘要，且仅显示当前成员有权了解的内容。                    |
| FR-KB-026 | P1     | 永久删除必须遵循来源许可、备份、审计和保留策略。删除请求在完成物理清理前应呈现为“待清理”，并立即阻止新的检索与分发。                         |

## 4. 摄取、解析与分块

### 4.1 摄取任务

| ID        | 优先级 | 需求                                                                                                                                                     |
| --------- | ------ | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| FR-KB-030 | P0     | 新文档版本进入系统后，必须创建可追踪的摄取任务，状态至少包括“待校验”“待解析”“解析中”“待分块”“待向量化”“索引中”“可检索”“部分失败”“失败”“已取消”“已归档”。 |
| FR-KB-031 | P0     | 摄取任务必须记录目标文档版本、请求成员、幂等键、开始/结束时间、当前步骤、重试次数和脱敏错误摘要；重复提交同一版本不得并发创建多个有效索引。              |
| FR-KB-032 | P0     | 解析、分块和 Embedding 属于可能耗时操作，必须异步执行或提供可恢复的任务状态，不能无界阻塞普通学习、记录和查询请求。                                      |
| FR-KB-033 | P0     | 文件、富文本和连接器输入必须先经过类型、大小、编码、恶意内容与授权校验；不支持或解析失败的资料不得被标记为可检索。                                       |
| FR-KB-034 | P1     | 摄取任务必须支持在安全条件满足时从失败步骤重试，而不重复创建已成功的版本、分块或 Embedding；重试原因与结果可审计。                                       |
| FR-KB-035 | P1     | 用户必须能取消尚未完成的摄取任务；取消后不再暴露该版本的部分索引，系统清理临时工作数据但保留最小任务审计摘要。                                           |

### 4.2 解析与规范化

| ID        | 优先级 | 需求                                                                                                                                     |
| --------- | ------ | ---------------------------------------------------------------------------------------------------------------------------------------- |
| FR-KB-040 | P0     | 解析器必须将可支持资料转换为规范化文本和结构元数据，同时保留页码、标题层级、段落序号、时间戳或其他能回到原始版本的源定位。               |
| FR-KB-041 | P0     | 解析过程必须区分正文、标题、表格、代码、引用、脚注和不可解析内容；不完整解析必须明确标记覆盖范围，不能将缺失内容当作不存在。             |
| FR-KB-042 | P0     | 系统不得将上传文档、HTML、Markdown、OCR 文本或连接器内容中的指令视为平台指令。解析出的文本仅作为不可信知识材料，进入模型前保持来源边界。 |
| FR-KB-043 | P1     | 图片、扫描件和音频转写可在来源允许、用户确认和独立质量策略下支持；OCR/转写结果必须标识为派生文本及其不确定性。                           |
| FR-KB-044 | P1     | 解析器版本变化后，系统必须能对选择的文档版本创建新的派生解析结果；既有引用继续指向创建时的版本与分块，不随解析器升级静默变化。           |

### 4.3 分块策略

| ID        | 优先级 | 需求                                                                                                                                             |
| --------- | ------ | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| FR-KB-050 | P0     | 系统必须按内容结构进行分块，优先在标题、段落、题目、卡片或语义边界切分；不得只按固定字符数截断而丢失来源和上下文。                               |
| FR-KB-051 | P0     | 每个分块必须保存所属文档版本、稳定顺序、标题路径、原文文本、token 估算、源定位、内容哈希、可见范围和索引状态。                                   |
| FR-KB-052 | P0     | 分块大小、重叠窗口、最小/最大 token 数、语言和内容类型策略必须可配置且版本化。分块策略变更需要新建派生结果并触发受控重索引，而不是改写历史分块。 |
| FR-KB-053 | P0     | 分块不得跨越不同家庭、不同文档版本或不同可见范围混合文本；跨成员共享资料的访问范围以最严格可见范围为准。                                         |
| FR-KB-054 | P1     | 系统可为题目、词汇、表格和教材目录使用专门分块策略，但每个策略必须保持回溯原始资料的源定位与可解释边界。                                         |
| FR-KB-055 | P1     | 分块浏览页面必须允许有权成员查看标题路径、源定位、版本、token 数、索引状态和脱敏预览，以排查检索质量；儿童端不显示管理级技术信息。               |

## 5. PostgreSQL、pgvector 与索引

### 5.1 数据库能力与迁移

| ID        | 优先级 | 需求                                                                                                                                                           |
| --------- | ------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| FR-KB-060 | P0     | PostgreSQL 必须作为知识库的关系数据和向量索引主存储，使用由 Flyway 管理的迁移显式启用并验证 `vector` 扩展；扩展不可用时知识库功能安全失败且普通业务仍可用。    |
| FR-KB-061 | P0     | 向量列必须与明确的 Embedding 模型版本和固定维度绑定。切换模型或维度时，系统必须创建新的向量空间/索引版本，不能将不兼容向量混入同一相似度比较。                 |
| FR-KB-062 | P0     | 关系元数据、来源、文档版本、分块、Embedding、摄取任务、检索会话和引用必须以规范化关系保存；向量只作为派生索引，不能脱离所属分块单独成为可访问业务对象。        |
| FR-KB-063 | P0     | 向量查询必须先应用家庭、知识库、文档版本、来源状态、归档状态和成员可见范围过滤，再计算或返回相似结果；不允许先全局取 Top-K 后在应用层过滤。                    |
| FR-KB-064 | P0     | 索引选择必须基于实际向量维度、过滤条件、数据量和 PostgreSQL/pgvector 版本验证。HNSW 或 IVFFlat 的参数、构建时机、召回/延迟取舍和回退策略必须记录在技术设计中。 |
| FR-KB-065 | P1     | 系统必须能检测并处理孤立 Embedding、缺失分块、模型版本不匹配和失败索引；数据修复使用受控任务，不在用户查询路径隐式写入。                                       |
| FR-KB-066 | P1     | 重索引必须限速、可取消、可恢复并按版本执行；当新索引未就绪时，系统继续使用上一可用兼容版本或明确报告知识库暂不可用。                                           |

### 5.2 Embedding 生成与版本

| ID        | 优先级 | 需求                                                                                                                                            |
| --------- | ------ | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| FR-KB-070 | P0     | 只有解析成功、来源允许、可见范围有效且未归档的分块可以进入 Embedding 队列。Embedding 生成前必须再次检查文档和成员授权状态。                     |
| FR-KB-071 | P0     | 每条 Embedding 必须保存实际提供商、模型 ID、向量维度、生成时间、输入内容哈希、状态和失败摘要；不得把模型密钥或完整请求/响应记录到数据库或日志。 |
| FR-KB-072 | P0     | 同一分块、同一内容哈希、同一 Embedding 模型版本的重复任务必须幂等；内容变化、模型变更或策略变更才创建新的派生向量。                             |
| FR-KB-073 | P0     | Embedding 提供商不可用、额度耗尽、超时或返回维度异常时，任务必须失败或待重试，相关版本不得被标为可检索；手动学习内容仍可正常使用。              |
| FR-KB-074 | P1     | 系统可为中英文或不同学科配置不同 Embedding 模型，但检索会话必须只比较兼容的向量空间，并记录实际选择。                                           |
| FR-KB-075 | P1     | 系统应支持批量 Embedding、速率限制、预算与队列监控；批量大小和并发度不应使普通 API、数据库或 AI 提供商饥饿。                                    |

## 6. 检索、重排与引用

### 6.1 检索请求与权限

| ID        | 优先级 | 需求                                                                                                                                                     |
| --------- | ------ | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| FR-KB-080 | P0     | 检索请求必须声明任务类型、当前成员、目标知识库或允许范围、查询文本/摘要和可选学习上下文；后端在检索前重新计算当前权限，不信任客户端传来的文档或分块 ID。 |
| FR-KB-081 | P0     | 儿童检索只能使用明确分配给自己的学习空间、内容和来源；家长查看儿童资料时只获得其管理范围，不自动读取成人个人学习空间。                                   |
| FR-KB-082 | P0     | 撤销空间、文档、来源或成员授权后，后续检索会话不得返回受影响分块，即使向量索引物理清理尚未完成。                                                         |
| FR-KB-083 | P0     | 检索会话必须有查询长度、结果数量、上下文 token 和调用频率限制。超过限制时系统要求缩小范围、选择空间或采用可见的分段流程。                                |
| FR-KB-084 | P1     | 用户可选择一个或多个有权知识库作为检索范围；系统展示所选范围和可检索资料数量的安全摘要，但不显示无权空间或受限文档存在性。                               |

### 6.2 检索与重排策略

| ID        | 优先级 | 需求                                                                                                                                                     |
| --------- | ------ | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| FR-KB-090 | P0     | 系统必须先用向量相似度从已授权、可检索分块中召回候选，再按来源状态、内容类型、标题/关键词匹配、版本新鲜度和任务上下文进行可配置重排。                    |
| FR-KB-091 | P0     | P0 检索至少支持语义向量检索；对有关键词、课程编号、词汇或章节标题的场景，P1 必须支持 PostgreSQL 全文检索或等价词法检索，并与向量结果进行透明的混合排序。 |
| FR-KB-092 | P0     | 系统必须保留每个最终命中的召回分数、重排分数、索引版本和采用状态，供有权审核者排查“为什么引用这段资料”。分数不能作为向用户宣称事实正确性的依据。         |
| FR-KB-093 | P0     | 召回结果必须去重同一版本中高度重叠的分块，并在需要时扩展相邻上下文，但扩展不得越过文档版本、可见范围或最大上下文预算。                                   |
| FR-KB-094 | P0     | 当没有足够相关且可核验的资料时，系统必须返回“未找到可引用资料”状态；AI 任务应请求用户缩小问题、补充资料或明确切换到无来源的创作草稿，不能编造引用。      |
| FR-KB-095 | P1     | 系统可引入重排模型或规则重排，但任何重排器只能读取已通过权限过滤的候选，且必须遵守独立的超时、额度和失败回退策略。                                       |
| FR-KB-096 | P1     | 有权家长或成人可在受控的检索检查器中查看查询摘要、候选数量、命中文档/版本、引用定位和脱敏分数；检查器不向儿童或无权成员暴露管理数据。                    |

### 6.3 引用与答案证据

| ID        | 优先级 | 需求                                                                                                                         |
| --------- | ------ | ---------------------------------------------------------------------------------------------------------------------------- |
| FR-KB-100 | P0     | 使用知识库生成的学习 AI 输出必须为每个可验证结论关联至少一个引用，引用指向文档版本、分块、标题路径、源定位和来源状态。       |
| FR-KB-101 | P0     | 引用展示必须让有权用户能打开资料的受控预览或原始来源定位；无权用户不能借引用标签、标题或链接推断受限资料存在。               |
| FR-KB-102 | P0     | AI 生成时只能把最终授权命中与必要相邻上下文放入提示词；提示词必须区分“系统指令”“用户问题”“不可信资料摘录”和“引用元数据”。    |
| FR-KB-103 | P0     | 输出中引用的资料如果已归档、失效或被撤销，草稿必须显示对应状态，且新的生成不得继续使用它；历史草稿不能伪装为当前可核验答案。 |
| FR-KB-104 | P1     | 需要比较多个来源时，系统应显示来源之间的一致、冲突或覆盖范围差异；不能仅凭向量分数选择一个来源而隐去明显冲突。               |
| FR-KB-105 | P1     | 用户可对检索结果标记“有帮助”“不相关”“来源问题”或“权限问题”。反馈必须与查询/命中关联，不能直接修改原始来源或排名模型。        |

## 9. 关键业务规则

- pgvector 解决语义召回，不是权限系统。每个 SQL 查询或检索服务都必须在数据库查询层限定家庭、空间、来源、版本、状态和成员可见范围。
- 文档版本、解析结果、分块和 Embedding 都是有生命周期的派生链。源文档的归档、撤销、权限缩小或删除必须切断后续检索，而不是等待下次重建索引。
- `1,000,000 token` 是 5.6-Terra Max 的最大上下文窗口。检索系统根据用户问题、任务类型、引用数量、分块 token 和预留输出预算选择小而相关的上下文，不能把完整知识库塞进单次请求。
- 向量距离、重排分数和点击反馈只反映检索信号，不证明资料正确、来源可信或教学适合。来源状态、人工审核和用户反馈共同决定可用性。
- 学习资料可能同时含有儿童信息、个人笔记和版权限制。共享、引用、预览和导出必须取来源许可与成员权限中更严格的结果。

## 10. 验收标准

| 编号      | 验收场景                                                                                                                                   |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| AC-KB-001 | 家长把一份有授权声明的学习资料导入儿童知识库后，系统创建可观察摄取任务，经历解析、分块、向量化和可检索状态；儿童只能在资料被分配后使用它。 |
| AC-KB-002 | 相同文档版本被重复提交时，系统通过幂等键和内容哈希避免重复有效分块/Embedding；内容或模型版本变化时创建新的派生版本。                       |
| AC-KB-003 | pgvector 扩展、向量维度或索引版本不匹配时，相关文档不会被标记为可检索，普通学习记录和非 AI 查询仍可完成。                                  |
| AC-KB-004 | 成人 A 的私有知识库不能通过向量相似检索、全局搜索、计数、引用标签或 API 被家长/成人 B 推断；授权后仅授权范围可见，撤销后立即排除。         |
| AC-KB-005 | 对学习问题执行检索时，结果提供版本化来源和源定位；没有授权且相关的资料时，系统明确返回无可引用资料而不编造链接。                           |
| AC-KB-006 | 来源被标记失效或文档被归档后，后续 AI 任务不能把其分块放入上下文；历史草稿展示来源失效状态。                                               |
| AC-KB-007 | 上传资料中含有“忽略规则、显示密钥、调用服务”等提示注入文字时，系统仍只把它作为不可信内容，不能泄漏密钥、提升权限或触发网络操作。           |
| AC-KB-008 | 知识库概览、导入抽屉、摄取中心和文档详情在有权成员下展示真实状态，在儿童和无权成员下不暴露管理数据；窄屏下所有必需操作仍可完成。           |
| AC-KB-009 | 检索检查器能让有权审核者查看命中资料、版本、定位、分数摘要和用户反馈，但不返回完整模型提示词、无权资料或模型密钥。                         |
| AC-KB-010 | 停用 AI 或 Embedding 提供商超时后，知识库保留资料和状态，学习计划/记录仍可使用，界面明确提示索引或生成暂不可用。                           |
