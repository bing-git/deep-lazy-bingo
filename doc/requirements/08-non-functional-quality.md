# 非功能与质量要求

## 1. 范围

本文件定义所有模块共同遵守的安全、隐私、可靠性、性能、可访问性、可观测性、测试、迁移和发布要求。功能通过页面演示不等于达到交付条件；以下要求是每个阶段验收的一部分。

## 2. 安全与隐私

| ID          | 优先级 | 需求                                                                                                                                                  |
| ----------- | ------ | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| NFR-SEC-001 | P0     | 生产环境的浏览器与 API 通信必须使用 HTTPS；会话 Cookie、令牌、CORS、CSRF 与安全响应头策略必须与认证方式一致，并经过自动化或手工验证。                 |
| NFR-SEC-002 | P0     | 数据库口令、AI 密钥、外部服务令牌和其他敏感配置不得存入源码、镜像、前端构建产物、日志或示例文件。部署环境必须通过受控环境变量或密钥管理设施提供密钥。 |
| NFR-SEC-003 | P0     | 若采用 YAML `ENC(...)` 加密敏感配置，解密主密钥必须只从部署环境注入；生产环境缺失主密钥时应用必须安全失败，不能回退为明文读取。                       |
| NFR-SEC-004 | P0     | 所有外部输入均由服务端校验、规范化并按上下文安全编码输出，以防 SQL 注入、XSS、路径遍历、反序列化和模板注入风险。                                      |
| NFR-SEC-005 | P0     | 后端访问外部或内网地址的功能必须遵循显式允许列表、解析后地址校验、协议/端口限制、超时、重定向限制和响应大小限制，防止 SSRF。                          |
| NFR-SEC-006 | P0     | 文件上传必须执行类型、扩展名、大小、内容或恶意文件检测、隔离存储和授权下载校验；上传文件不能被当作服务器可执行内容。                                  |
| NFR-SEC-007 | P0     | 密码必须使用经过验证的现代哈希方案保存；登录、重置、邀请、AI 与导出接口必须按风险施加速率限制。                                                       |
| NFR-SEC-008 | P1     | 系统必须定期扫描依赖、锁文件、容器镜像和仓库中的泄漏密钥；高危发现阻止发布或有期限地记录例外。                                                        |

## 3. 数据、迁移与备份

| ID           | 优先级 | 需求                                                                                                            |
| ------------ | ------ | --------------------------------------------------------------------------------------------------------------- |
| NFR-DATA-001 | P0     | 所有关系型数据结构和必要基础数据变更必须由版本化 Flyway 迁移完成；已成功应用的迁移不得修改。                    |
| NFR-DATA-002 | P0     | 应用不得在生产环境通过 ORM 自动创建、更新或删除表结构；迁移失败必须明确阻断部署，不能自动删除数据或不可逆回滚。 |
| NFR-DATA-003 | P0     | 所有业务对象必须持有必要的家庭和成员归属，关键记录需有创建/修改时间与操作者；时间存储使用 UTC。                 |
| NFR-DATA-004 | P1     | 发布前必须存在经过验证的数据库备份与恢复步骤。高风险、长时间或不可逆迁移必须在预发布验证，并制定独立执行策略。  |
| NFR-DATA-005 | P1     | 用户上传资料、AI 草稿、审计和导出文件必须各自具有保留、访问控制和清理策略；备份不应成为绕过权限的读取通道。     |

## 4. API、错误与兼容性

| ID          | 优先级 | 需求                                                                                                              |
| ----------- | ------ | ----------------------------------------------------------------------------------------------------------------- |
| NFR-API-001 | P0     | 对外业务 API 必须使用版本化 `/api/v1` REST/JSON 契约，并以 OpenAPI 3 描述认证、请求、响应、错误、分页与权限要求。 |
| NFR-API-002 | P0     | API 响应不得直接暴露数据库实体、堆栈、SQL、内部地址、密钥或供应商原始错误；错误格式在各模块间保持一致。           |
| NFR-API-003 | P0     | 列表接口必须提供稳定分页、排序和过滤语义；写接口应为创建、更新、删除和重复提交定义幂等或冲突处理规则。            |
| NFR-API-004 | P0     | 破坏性 API 变更必须通过新主版本、兼容层或明确迁移期交付；前端生成类型/客户端必须与已发布契约一致。                |
| NFR-API-005 | P1     | 每个请求必须可关联请求 ID；该 ID 可在安全日志、错误提示和运维排查中使用，但不携带用户敏感内容。                   |

## 5. 性能与可靠性

| ID           | 优先级 | 需求                                                                                                                                                                |
| ------------ | ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| NFR-PERF-001 | P0     | 在发布定义的参考部署与基准数据集下，非 AI 的普通读取 API 的服务端 p95 响应时间目标为不高于 500ms，普通写入 API 目标为不高于 800ms；无法达到时需记录瓶颈与处理计划。 |
| NFR-PERF-002 | P0     | AI、导出、文件处理、服务探测和其他可能耗时的操作不得无界阻塞普通业务请求；应提供超时、取消、状态查询或异步任务策略。                                                |
| NFR-PERF-003 | P0     | 前端必须避免首次加载全部业务数据；列表、搜索、图表和通知按需请求，并显示加载与失败状态。                                                                            |
| NFR-PERF-004 | P1     | 发布前必须定义参考硬件、家庭规模、记录量和并发基准，并以可重复脚本或测试记录性能结果。                                                                              |
| NFR-REL-001  | P0     | 数据库、Redis、AI、文件存储或外部服务不可用时，系统必须以明确错误和可恢复状态处理；不应造成数据损坏或无限重试。                                                     |
| NFR-REL-002  | P0     | 写入关键业务记录时，失败响应不得被误显示为成功；客户端重试必须配合服务端幂等或冲突控制。                                                                            |
| NFR-REL-003  | P1     | 应用必须暴露不含敏感数据的存活与就绪状态，供部署和监控使用。                                                                                                        |

## 6. 可用性、可访问性与前端质量

| ID         | 优先级 | 需求                                                                                                                                                      |
| ---------- | ------ | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| NFR-UX-001 | P0     | PC 与移动浏览器均可完成 P0 关键流程：登录、查看工作台、创建/完成学习任务、记录运动/餐食和退出。布局不得因窄屏发生不可操作的遮挡、文字溢出或横向内容丢失。 |
| NFR-UX-002 | P0     | 交互控件必须有可见焦点、可访问名称和键盘可达性；仅图标按钮必须提供工具提示或等价文字。                                                                    |
| NFR-UX-003 | P0     | 颜色不是状态的唯一表达方式。图表、表单校验、趋势、服务状态和任务状态必须同时提供文本、图标或模式提示。                                                    |
| NFR-UX-004 | P0     | 页面必须实现加载、空、失败、无权和完成状态；禁止用模拟数据填充生产空态。                                                                                  |
| NFR-UX-005 | P1     | 主题必须通过统一设计令牌影响 Art Design Pro 壳、Element Plus 封装组件、图表和自定义模块；不得仅替换背景色。                                               |
| NFR-UX-006 | P1     | 支持当前主流 Chrome、Edge、Safari 和移动浏览器的最近两个主要版本；兼容范围变更需在发布说明中记录。                                                        |

## 7. 可观测性与运维

| ID          | 优先级 | 需求                                                                                                                                  |
| ----------- | ------ | ------------------------------------------------------------------------------------------------------------------------------------- |
| NFR-OPS-001 | P0     | 应用日志必须使用结构化格式，包含时间、级别、请求 ID、模块、事件和脱敏上下文；不得记录密码、令牌、完整会话、敏感正文或模型原始上下文。 |
| NFR-OPS-002 | P0     | 认证、授权拒绝、迁移、AI 调用、服务探测、导出和高风险管理动作必须产生可查询的运行或审计事件。                                         |
| NFR-OPS-003 | P1     | 系统必须暴露聚合指标，例如请求量、错误率、延迟、任务队列长度、AI 用量和探测结果；指标标签不得包含成员姓名、完整 URL 或秘密。          |
| NFR-OPS-004 | P1     | 部署文档必须说明配置、密钥注入、迁移、备份、恢复、升级、日志位置和应急停用 AI/外部探测的方式。                                        |

## 8. 测试、质量门禁与发布

| ID            | 优先级 | 需求                                                                                                                                      |
| ------------- | ------ | ----------------------------------------------------------------------------------------------------------------------------------------- |
| NFR-TEST-001  | P0     | 每个 P0 模块必须有与风险相称的单元、集成或端到端测试。身份、家庭隔离、对象级授权、AI 审核、服务地址校验和文件访问必须具备自动化负向测试。 |
| NFR-TEST-002  | P0     | 后端测试必须覆盖空数据库首次迁移和已有数据库升级；前端测试必须至少覆盖家长与儿童的关键权限路径。                                          |
| NFR-TEST-003  | P0     | CI 必须执行后端构建与测试、前端类型检查与构建、迁移校验、格式化/静态检查及高危依赖扫描。失败不得被静默忽略。                              |
| NFR-TEST-004  | P1     | 发布前应运行端到端测试，覆盖登录、家庭隔离、学习闭环、健康隐私、服务目录和 AI 关闭时的降级行为。                                          |
| NFR-TEST-005  | P1     | 质量门禁应包含 SonarQube/SonarCloud 或等价静态质量检查、秘密扫描、容器镜像扫描与可追踪的例外审批。                                        |
| NFR-RELSE-001 | P0     | 发布必须具备版本号、变更说明、迁移说明、已知风险、回退或前向修复策略；不得把无法恢复的数据迁移作为无说明的小版本变更。                    |

## 9. 验收标准

| 编号       | 验收场景                                                                                                 |
| ---------- | -------------------------------------------------------------------------------------------------------- |
| AC-NFR-001 | 生产配置与构建产物中不包含可用数据库密码、AI 密钥或家庭服务凭据；缺少必需密钥时应用以明确安全状态失败。  |
| AC-NFR-002 | 新环境和已迁移环境均可运行全部 Flyway 迁移；迁移错误会阻断启动，且不会自动删除数据。                     |
| AC-NFR-003 | 在定义的基准环境中，普通非 AI API 满足相应 p95 目标；AI 或导出超时不阻断用户继续使用普通记录与查询功能。 |
| AC-NFR-004 | 键盘用户可完成登录、打开任务、提交单选练习和保存运动记录；图标按钮有可访问名称，窄屏没有必要动作被遮挡。 |
| AC-NFR-005 | CI 在引入类型错误、失败测试、迁移错误、关键授权回归或高危依赖时失败，并给出可定位的检查结果。            |
| AC-NFR-006 | 备份恢复演练能按文档恢复到可启动、可登录并可读取授权数据的状态，演练结果和发现的问题被记录。             |
